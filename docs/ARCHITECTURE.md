# 做多量化选股系统技术架构说明

> 目标：用 Qt 6 Widgets + QCustomPlot 构建一款以「涨停板接力打板」为基线、
> 支持多维度做多评分的桌面量化选股客户端 —— **做多量化选股系统**，
> 覆盖**范围界定 → 数据接入 → 策略引擎 → 交互呈现 → 本地存储**
> 的完整闭环。策略口径为单一「均衡做多」因子权重（版本管理与排名对比模块已下线）。

---

## 一、范围界定

### 1.1 目标市场与交易品种

| 维度 | 界定 | 理由 |
|---|---|---|
| 市场 | A 股沪深主板 / 创业板 / 科创板 | 打板策略依赖涨跌停制度与 T+1 交收 |
| 排除 | 北交所（30cm）、ST/退市风险股、新股 | 涨跌幅体系不同（10%/20%/30%）、基本面风险、上市初期无涨跌停参考 |
| 交易品种 | 股票现货 | 打板依赖涨停价挂单，不适用于 ETF/可转债（无涨跌停或 T+0） |
| 策略类型 | **接力打板**（T 日封板买入 → T+1 溢价兑现） | 不含首板当日打板（一进二才是主力战场） |
| 计价方式 | 不下单 | 客户端定位为「选股 + 决策辅助」，交易由券商端执行，规避程序化交易监管风险 |

> **制度约束（必须内建到产品里）**：2025-07-07 沪深北交易所《程序化交易管理实施细则》实施，
> 高频交易认定标准为单账户每秒申报/撤单合计 ≥300 笔或单日合计 ≥2 万笔，并重点监控
> 「频繁瞬时撤单」「频繁拉抬打压」等行为。**虚假封单诱导、极速抢板等路径已被切断**，
> 同时融券 T+0 套利通道关闭。因此本客户端**只做选股与监控，不做自动下单**。

### 1.2 选股策略核心逻辑：五层流水线

打板最常见的错误是**把不同阶段的标准混着用**（首板看封单、二板看换手、三板看筹码）。
本客户端用严格分层结构杜绝这一点：

```
L0 情绪闸门  → L1 通用硬排除 → L2 板块效应 → L3 分层量价 → L4 评分排序
```

#### L0 情绪闸门（MarketRegime，先决条件）

同一只票在不同情绪周期里结果天差地别。**退潮期最好的板也不碰。**

| 指标 | 健康 / 可做 | 危险 / 空仓 | 客户端实现 |
|---|---|---|---|
| 涨停家数 | ≥40（强市 ≥60） | <30 | `minLimitUpCount` |
| 跌停家数 | <5 | **≥8 时高位接力风险极大** | `maxLimitDownCount` |
| 炸板率 | <20% | **>40% 停手**，>30% 降仓 | `maxBrokenRate` |
| 最高连板高度 | 稳定或向上拓展 | 断板 / 梯队断层 | `minMaxBoardHeight` |
| 连板晋级率 | >30% | <15%~20% 为冰点 | `minAdvanceRate` |

阶段映射与仓位建议：

| 阶段 | 触发 | 建议 |
|---|---|---|
| 冰点期 | 涨停<30 且 炸板率>30% | 空仓，仅建观察池 |
| 回暖期 | 涨停≥30，炸板率<35% | 小仓试错（≤20%），一进二 |
| 主升期 | 涨停≥40，炸板率<25% | 主攻二进三/三进四（≤60%） |
| 高潮期 | 涨停≥60 且 最高板≥5 | 减仓（≤30%），只做龙头 |
| 退潮期 | 跌停≥8 或 炸板率>40% | **禁止出手** |

#### L1 通用硬性排除

| 条件 | 阈值 | 依据 |
|---|---|---|
| ST / 退市风险 | 排除 | 5% 涨跌幅，生态完全不同 |
| 北交所 | 排除 | 30cm 涨跌幅，连板含义不同 |
| 一字板 | 排除 | 无换手 → 筹码断层，开板易集中抛售 |
| 股价 | 2–50 元 | 高价股上涨想象空间小 |
| 流通市值 | 15–150 亿 | 太小易被操纵；太大资金难拉动 |
| 上市天数 | ≥60 日 | 缺历史涨停基因参考 |

#### L2 板块效应

**孤板不做。** 用涨停池自带的 `hybk`（东财行业板块）字段做当日板块内涨停家数统计，
要求同板块涨停 **≥3 家**。这是区分「主线龙头」与「跟风杂毛」的最有效单一条件。

#### L3 分层量价（核心：不同阶段看不同指标）

**首板（1 板）——看换手率**
换手率按流通市值分档（客户端内建三档，取值内置于 `Indicators.cpp` 的分档表）：

| 流通市值 | 合格线 | 黄金区间 | 危险线 |
|---|---|---|---|
| <50 亿 | ≥8% | 10%–20% | >25% |
| 50–200 亿 | ≥5% | 6%–15% | >20% |
| >200 亿 | ≥3% | 3%–8% | >15% |

- 换手 <3%~5%：缩量秒板/一字板，筹码锁死，次日晋级概率极低
- 换手 >25%：爆量板，做多动能一次透支，次日无人接力
- 另需：量比（当日量/前5日均量）**1.5–3 倍**；首次封板 **≤10:30**；当日开板 **≤2 次**；
  近 20 日涨停次数 ≥1（涨停基因）；前一日涨幅 ≤9.5%（避免高位接力）

**二板（2 板）——看强度（换手率降级为辅助）**
- 封单额/当日成交额 **≥20%**
- 封单额/流通市值 **≥1%**
- 量能相对首板 **1.2–3 倍**（内置「允许缩量不缩势」开关，默认放行）
- 隐含卡位：同板块同高度中率先封板

**三板及以上——看龙头地位**
- 必须是板块核心标的（板块涨停数 ≥3）
- 突破前周期高度压制
- **≥6 板坚决不碰**（缩量加速板 + 异动监管 + 停牌核查风险）
- 4–6 板为谨慎区

#### L4 评分排序（不改变筛选结果，只决定先后）

8 个因子归一化后加权：换手 / 量能 / 封板时点 / 封单 / 板块 / 连板高度 / 涨停基因 / 均线形态。
权重取内置默认值。≥5 板额外扣分（风险溢价）。输出 A/B/C 三级。

### 1.3 行情数据来源与实时更新

| 数据 | 接口 | 用途 | 更新方式 |
|---|---|---|---|
| 涨停池 | `push2ex.eastmoney.com/getTopicZTPool` | 核心选股输入 | 盘中 20s 轮询 |
| 炸板池 | `getTopicZBPool`（**必须带 `sort=zbc:desc`**，否则 pool 为空） | 炸板率、烂板识别 | 同上 |
| 跌停池 | `getTopicDTPool` | 跌停家数（退潮信号） | 同上 |
| 日 K（前复权） | `web.ifzq.gtimg.cn/appstock/app/fqkline/get` | 量比 / 均线 / 涨停基因 | 按需拉取，1h 缓存 |
| 全市场快照 | `vip.stock.finance.sina.com.cn/.../getHQNodeData` | 估值/换手/市值（55 页并发约 3s） | 60s 缓存 |
| 单只实时行情 | `hq.sinajs.cn/list=`（GBK） | 按需补快照（竞价判定 / 盘中价格） | 按需 |

**关键工程细节（均为实测踩坑后固化）**
- 东财涨停池价格字段 `p`/`ztp` 单位是 **0.001 元**，必须除以 1000。
  标定方式：与新浪实时价逐一比对，并用 `成交额/现价/流通股本` 反算换手率与 `hs` 交叉验证。
- 腾讯 `qt.gtimg.cn` 返回 **GBK**，其余为 UTF-8。客户端用 Win32 `MultiByteToWideChar(CP936)`
  自实现解码，**不依赖 Qt5Compat**（该模块不随 qtbase 附带）。
- 东财/新浪接口需带 `Referer`，否则返回空。
- 免费接口无 SLA，生产必须自建缓存与限流：客户端内置**每主机令牌桶**（16 req/s）、
  指数退避重试（0.5s/1.2s/2.0s）、并发上限 10。

### 1.4 数据存储与管理

SQLite（Qt SQL 模块），核心表：

| 表 | 主键 | 用途 |
|---|---|---|
| `trade_journal` | id | 交易日志（成交流水：买入 + 可选的了结信息） |
| `recommend_plan` | trade_date | 做多计划快照（离线兜底） |
| `daily_kline` | (code, trade_date) | 日K缓存，避免重复请求行情接口 |
| `sentiment_daily` | trade_date | 复合情绪序列留档（趋势 / 退潮确认） |
| `review_daily` / `forecast_*` / `assistant_*` | — | 复盘助手（日报 / 预判 / 评估 / 规则 / 策略 / 教训） |
| `app_setting` | key | 跨会话键值配置 |

> **交易日志的双后端**：交易日志是唯一需要长期留档、可能跨设备查看的数据，因此它不只存在 SQLite 里。
> `storage/JournalStore` 抽象出统一接口（`trades / addTrade / updateTrade / deleteTrade / lastError`），
> 由两个后端实现：`storage/Database`（SQLite，本地默认与兜底）与 `storage/MySqlStore`（MySQL，服务器集中存储）。
> 界面层 `ui/JournalPanel` 只依赖接口，切换后端不改一行 UI 代码；
> MySQL 不可用时自动回退 SQLite，页面顶部显示当前生效的后端。
> MySQL 侧首次连接自动建库建表，表结构与 SQLite 后端字段一一对应，因此历史流水可整体搬迁。

WAL 日志模式 + `synchronous=NORMAL`，保证写入吞吐不阻塞 UI 线程。

> **凭据类配置不入库**：SMTP 授权码与 AI 分析 API Key 都落在用户私有目录的独立 JSON 文件里
> （`notify_config.json` / `ai_config.json`），密文字段分别为 `passwordEnc` / `apiKeyEnc`
> （DPAPI，绑定当前 Windows 用户）。AI 分析密钥由用户自设，程序不内置、不读环境变量，
> 未配置时功能不可用并给出明确提示；详见 `README.md` §10.2。

### 1.6 交易计划（TradePlan）：把「选出来」变成「能执行」

选股只回答「买哪只」，但真正下单还需要「什么价买、涨到哪走、跌到哪撤」。
`core/TradePlan.h` 把这三段价格显式建模为**区间**（而非单点），因为挂单成交存在滑点，
且区间上下沿对应不同强度的信号：

| 区间 | 语义 | 计算锚点 |
|---|---|---|
| **买入区间** `[buyLow, buyHigh]` | 次日可接受的追高价格带，涨停价本身落在区间内 | 下沿 = MA5 承接位（缺失时用涨停价 −2%~3%）；上沿 = 涨停价 + 追高容忍（首板 +3% / 二板 +2% / 三板+ 不给溢价） |
| **止盈区间** `[tpLow, tpHigh]` | 分批兑现价格带 | 下沿 = 买入中枢 +3%（冲高落袋）；上沿 = 次日涨停价（主板 +10% / 双创 +20%，接力最高空间） |
| **止损区间** `[slLow, slHigh]` | 跌破下沿无条件走；跌破上沿减仓 | 上沿 = 涨停当日最低价（**炸板即走**，打板铁律）；下沿 = 上沿 × 98.5%（1.5% 容错带，防插针） |

配套输出：
- **盈亏比** = (止盈中枢 − 买入中枢) / (买入中枢 − 止损中枢)
- **建议仓位** = 情绪阶段总仓上限 × 评分系数 × 板块效应系数，单票封顶 20%
- **依据话术**：每个价格都带一句可核对的说明（用哪个锚点、为什么），杜绝黑盒数字

**闸门拦截时的降级策略（关键设计）**：
情绪闸门是硬否决 —— 退潮/冰点期**不给仓位**（`positionPct = 0`），但**仍然输出完整的
观察名单**（含全部三段区间）。理由：用户要的是「打开就能看到算好的东西」，
空表等于没做；而「不可执行 ≠ 不显示」在语义上并不冲突。
观察名单分两梯队：第一梯队是因子全达标、仅因市场环境不允许的标的；第二梯队是
分层量价差一点点被淘汰的标的（情绪修复后最先达标）。

```
└──────────────────────────────────────────────────────────────────────┘
```

### 2.1 分层原则

1. **core 层零依赖**：`Types.h` / `Indicators` / `TradePlan` 不含任何 Qt Widget
   或网络代码，纯数据结构与计算函数，可独立单元测试。
2. **UI 不含业务逻辑**：所有筛选、评分、情绪判定都在 strategy 层；UI 只负责渲染与
   交互转发，策略阈值固定内置于各引擎（`FilterPipeline` / `Scorer` / `MarketRegime` /
   `SentimentEngine` / `TradePlan`）。
3. **数据层单一门面**：`DataHub` 聚合所有 Source，对外只暴露信号与缓存查询；
   UI 永远不直接碰 HTTP。
4. **策略层纯函数化**：`FilterPipeline::run()` 输入池子 + 上下文，输出候选列表，
   无副作用、可重复执行。

### 2.2 多维度做多因子选股（叠加在打板策略之上）

| 层 | 落点 | 职责 |
|---|---|---|
| 配置 | `strategy/FactorConfig.*` | 6 个维度的启停 / 权重 / 过滤门槛 / 参与方式，组合规则、综合分门槛、TopN；JSON 持久化在 `app_setting.factor.config`；出厂默认即「均衡做多」（`FactorConfig::balanced()`），版本管理下线后全局只有这一套配置 |
| 引擎 | `strategy/MultiFactorEngine.*` | 纯计算：趋势 / 动量 / 资金流向（代理口径）/ 基本面 / 波动率 + 打板核心，输出综合评分排序与维度贡献度分解 |
| 实盘 | `strategy/RecommendEngine::applyFactorRanking()` | 装配后把综合分、贡献度写回 `TradePlan`，按综合分重排，过滤项降级为观察 |
| 回测 | `backtest/BacktestRunner::run()` | 直接调用同一个 `rank()`；被过滤 / 未入 TopN 的标的不参与结算，逐笔 CSV 输出维度贡献占比 |
| 展示 | 综合分与贡献度随 `TradePlan` 输出，供推送 / 复盘 / CSV 使用（维度明细表与权重配置入口已随研究型入口移除） |

### 2.3 定价的第二套锚点：筹码分布与量能确认

`core/TradePlan.cpp` 原本只用价格锚（涨停价 ± 容忍度、MA5、当日最低价）推导三段区间。
现在引入**筹码锚**与**量能判据**，回答「真实的支撑与压力在哪、抛压是否衰竭」：

| 环节 | 落点 | 职责 |
|---|---|---|
| 成本重建 | `core/ChipDistribution.*` | 用**不复权真实价**日 K 重建成本分布：每根 K 的成交量按三角形分布（峰顶取当日均价）摊到 `[最低价, 最高价]`，按每日 0.985 衰减加权，落到 140 格价格网格；平滑后取半高宽为峰区上下沿 |
| 峰定位 | `Chip::supportBelow()` / `pressureAbove()` | 输出当前价下方最近的支撑峰（峰顶低于现价、筹码占比 ≥2%）与上方最近的压力峰 |
| 承接位 | `core/TradePlan.cpp` | 买入下沿锚在支撑峰上沿（筹码断层时退回 MA5，再退回涨停价 − 容忍度）；止损上沿锚在支撑峰下沿；止盈上沿收敛到压力峰上沿 |
| 量能判据 | 同上 | 量比（当日量 / 前 5 日均量）驱动：缩量衰竭(<0.8) / 温和放量确认(1.5~2) / 放量击穿(≥1.5 且跌破承接位) / 放量破位(≥1.5 且跌破密集区下沿) |
| 破位缓冲 | 同上 | 缩量破位可能假跌破 → 止损缓冲放宽到 2.5%；放量破位 → 收紧到 1.5% |

设计约束：
- **零未来函数**：K 线先 `sliceTo(regime.date)` 截断，筹码分布只用决策日及之前的数据；
- **口径一致**：筹码分布必须用不复权真实价，否则除权日与涨停价对不上；
- **优雅降级**：日 K 缺失或不足 10 根时不出筹码分布，自动退回 MA5 / 涨停价口径，并在 `buyBasis` 写明「保守估计」；
- **不伪造分时事实**：外盘/内盘与逐笔主动买卖当前无数据源，用日线等价代理
  （主动买强度 =(收盘−最低)/(最高−最低)、日均价 = amount/volume），文案中明确标注口径。

一致性约束：两条链路的输入统一由 `MultiFactorEngine::makeInputs()` 构造并按
`sliceTo(asOf)` 截断；配置来自同一份 `app_setting`；`--selftest` 做「实盘装配链 ==
回测直接链」断言，离线门禁 `core_checks` 验证贡献度守恒、权重归一化、过滤规则与
统一输入构造。原有 `FilterPipeline` 五层硬筛选与 `Scorer` 8 因子保持不变，
打板评分作为「打板核心」维度参与组合且默认权重最高。各维度的精确定义、权重
配置与组合规则见 `README.md §7`。

### 2.4 关键实现要点

**A. 数据层**
- `HttpClient` 复用单个 `QNetworkAccessManager`（连接复用），内置**每主机令牌桶**限流
  （16 req/s/host）与指数退避重试；错误通过 `requestFailed` 统一上报。
- `TextCodec` 自实现 UTF-8/GBK 双编码支持，规避 Qt5Compat 依赖。
- `SnapshotSource` 对新浪返回的「非法 JSON」做正则修复兜底（key 无引号）。
- `DataHub` 内存缓存：K线按代码缓存 TTL 1h，快照 TTL 60s。

**B. 策略层**
- `MarketRegime::computeBase()` 从三个池子直接统计；`evaluate()` 做阶段判定 + 闸门。
  闸门是**硬否决**：不通过时 `FilterPipeline::run()` 直接返回空结果，UI 显示
  「本轮不产生候选」。
- `FilterPipeline` 分层执行，每层淘汰都写入 `rejectReason`，UI 可展开查看
  「为什么被淘汰」——这是选股工具的核心可信度来源。
- `FilterPipeline::buildSectorCounts()` 用 `hybk` 做板块计数，供 L2 使用。
- `Scorer::breakdown()` 返回 8 个分项原始分，供首页「状态依据」话术与自检输出消费。
- `Indicators::limitUpCount()` 按板块涨跌幅规则（10%/20%/30%）判定历史涨停，
  这是「涨停基因」指标的基础。
- `RecommendEngine::build()` 把候选装配成 `RecommendBundle`：
  闸门放行 → 可执行荐股（带真实仓位）；闸门拦截 → 观察名单（仓位恒为 0）。
  它统一以 `lastPassedPreGate()` 为达标名单来源 —— 因为 `run()` 在闸门拦截时
  会清空返回值，直接用返回值会在拦截场景丢失全部标的。
- `core/TradePlan` 是零 IO、零 GUI 的纯计算层，GUI / 自检 / 离线复盘共用同一套
  区间计算逻辑，保证「界面上看到的数字」与「自检打印的数字」必然一致。

**C. 「打开即见」的工程保障**

| 场景 | 机制 |
|---|---|
| 网络正常 | 启动即自动拉数 → 自动分析 → 自动填充首页，无需任何点击 |
| 网络不通 | 启动时先读 `recommend_plan` 表的本地缓存（带 `[缓存]` 标识），数据到达后自动覆盖 |
| 周末/节假日 | 当天涨停池为空时自动向前回退最多 7 个交易日，并在标题栏标注「【YYYY-MM-DD 交易日数据】」 |
| 闸门拦截 | 输出观察名单（仓位 0），而非空白页 |
| 日 K 未就绪 | 区间退化为「涨停价 ± 百分比」的保守估计，依据话术里显式注明；K 线到达后自动重算 |

**D. 图表层（单一 K 线视图）**
- `ChartPanel` 只保留一个 QCustomPlot，内部用 `QCPLayoutGrid` 纵向排三个 `QCPAxisRect`：
  价格（含 MA/BOLL 与涨停标记，stretch 5）→ 成交量（含均量线，1.3）→ 指标副图（1.9）。
  三个轴矩形的自带轴用 `hideUnusedAxes()` 隐藏，只留自定义的一组。
- 涨跌色遵循 A 股惯例（**涨红跌绿**）；价格从 `p/1000` 还原，蜡烛用 `QCPFinancial`。
- 周期切换在 `ChartPanel::setPeriod()` 内做本地聚合（周=同历年周号，月=同历年月；
  开=首开 / 收=末收 / 高低取极值 / 量额求和），不额外请求接口。
- X 轴三根联动：`rangeChanged` → `syncX()`，`m_syncing` 防递归 + `QSignalBlocker` 抑制回环，
  随后 `fitY()` 按当前可见区间重算 Y（并留 6% 边距）、`updateDateTicks()` 按可见跨度选粒度
  （日→MM-dd / 周→yy-MM / 月→yyyy-MM），避免缩放到一年后刻度重叠成黑块。
- 十字光标为 overlay 图层上的两条 `QCPItemStraightLine` + 右上角 `QCPItemText` 读数条
  （日期 / OHLC / 涨跌幅 / 量额）；`mouseDoubleClick` 复位到末 120 根。
- 指标（SMA / EMA / MACD / KDJ / RSI / BOLL）在 `ChartPanel` 内部计算，未成熟区间输出 NaN，
  `QCPGraph` 会自动断线，不会画出假的 0 值。
- 长历史数据走 `DataHub::refreshChartKline()` 的**独立通道**（独立 `KlineSource` 实例 +
  独立缓存 `m_chartKlineCache` + 独立信号 `chartKlineReady`），与筛选用的 120 日 `m_klineCache`
  完全隔离 —— 否则次新股判定（按 K 线根数）与量比口径会被 480 日长序列污染。

```
        │
        ▼
AiAnalysisClient::post()  ← 二次门禁（ready 为 false 不创建 QNetworkRequest）
        ▼  Bearer 头携带密钥；请求体不含密钥
```

- 密钥明文只在内存；错误文案、日志、请求体、CSV、界面回显都不会出现完整密钥（回显仅掩码）。

**③ 边界契约集中在 `AiAnalysisSpec`（零 GUI / 零网络 / 零 IO）**

| 维度 | 约束 | 强制手段 |
|---|---|---|
| 分析目标 | 只解读单个结构化计划快照的自洽性、纪律与可见风险；不预测、不下指令、不选股 | 固定 system prompt 第一段 |
| 输入范围 | 18 个白名单字段；账户 / 密钥 / 原始 K 线 / 备注长文一律丢弃；缺失置 `null` | `sanitizeInput()` + 界面原文预览 |
| 输出结构 | 固定 6 键 JSON、`conclusion` 三值枚举、数组条数与文本长度上限 | `parseResult()` 严格校验，不合规整份丢弃 |
| 判断原则 | 只引用给定字段、矛盾→存疑、缺失→数据不足、以本地计算为准、`temperature=0` | prompt 第四段 + `evidence.field` 白名单校验 |
| 展示一致性 | 固定 5 段 HTML（摘要 / 依据 / 风险 / 纪律 / 不确定性） | `renderResult()` 唯一渲染出口 |

- 四段边界文本同时用于 `systemPrompt()` 与界面「分析边界」展示，改一处即全链路生效；
  `core_checks` §13 对这些约束做离线断言，防止后续改动放宽边界。

## 五、策略有效性说明

客户端的所有阈值均来自公开复盘统计与投顾体系，并已用真实数据交叉验证。**三点必须坦率说明：**

1. **口径差异**：同一指标在不同公开统计中差异很大（如首板换手黄金区间有 5–15%、
   6–18%、10–20% 三种说法）。客户端采用其中一套明确口径写入
   引擎内的固定常量，保证同一版本内判定标准一致、可复核。
2. **环境逆风**：当前 A 股平均连板高度已从 2015 年的约 7 板压缩至约 3.2 板，
   打板胜率降至约 20%–30%，炸板率长期在 45%–60%。策略整体处于逆风环境，
   这正是情绪闸门被设计为**硬否决**而非软提示的原因。
3. **历史统计不可尽信**：涨停排队成交的真实性无法还原，仅凭历史数据的收益推演通常偏乐观。

> **免责声明**：本客户端为量化研究工具，所有输出基于公开数据与量化分析，仅供参考，
> 不构成投资建议。打板属极高风险短线交易，单次判断失误的单日亏损可达 8%–20%。
> 市场有风险，投资需谨慎。任何投资决策应结合个人风险承受能力、资金状况和投资目标
> 独立判断，必要时咨询持牌专业机构。过往表现不预示未来收益。

### 6.2 修复过的真实缺陷（均已在代码中修正）

1. **东财价格量纲**：`p`/`ztp` 是 0.001 元而非「分」，早期按 ÷100 解析导致股价放大 10 倍、
   硬排除层误杀全部标的。已按 ÷1000 修正并写入注释。
2. **URL 转义**：`QString::arg` 中写 `%%3A` 会原样输出双百分号，导致接口返回空池。
3. **HTTP 队列索引错位**：遍历中 `takeAt(i)` 会让后续元素前移，正序取出会取错元素并丢任务；
   已改为倒序取出。
4. **闸门拦截时漏斗全 0**：用户无法看出各层淘汰情况；改为闸门拦截时仍跑完管线填充统计，
   但最终输出空候选。
5. **代理误用**：把 `http_proxy` 套用为 Qt 代理会触发 `TLS initialization failed`；
   改为默认直连，仅在 `DABAN_FORCE_PROXY=1` 时启用。
6. **QCustomPlot 2.x API 适配**：1.x 的 `QCPPriceAxis` / `addLayout` / `setTickLabels(QStringList)` /
   `QCPBarSet` / `setMarker` 在 2.x 均已变更，统一由 `ui/QcpAdapter.*` 封装
   （`QCPAxis` + `QCPAxisRect::addAxis` + 自定义 `QCPAxisTicker` + `QCPBars`）。
7. **三池并发广播竞态**（★ 导致「今天涨停 0 家」）：涨停/炸板/跌停三个请求并发发出，
   原实现**任一先返回就广播全量**，此时其余两个池还是空的 —— 上游收到
   「涨停 0 / 炸板 0 / 跌停 N」的残缺快照，选股结果随之全空。
   已改为**三类池全部 settle（成功或失败）后才广播，且只广播一次**。
   修复前实测涨停 0 家，修复后 82 家。
8. **情绪快照日期硬编码为今天**：`MarketRegime::computeBase()` 写死 `QDate::currentDate()`，
   非交易日回退到历史交易日时会把数据错标为「今天」，缓存也会存错键。
   已改为接收实际交易日参数。
10. **闸门拦截时荐股名单丢失**：`FilterPipeline::run()` 在闸门拦截时清空返回值，
    荐股层若直接用返回值会拿不到任何标的。已统一以 `lastPassedPreGate()` 为达标名单来源。

### 6.3 环境相关限制（非代码问题）

- **应用控制策略**：本机对新建 exe 有 WDAC/AppLocker 类策略，部分目录下的可执行文件
  会被拦截或禁网；自检在允许目录下可完整运行。
- **QApplication 初始化**：在受限会话中创建 GUI 版实例可能失败（0xC0000409），
  因此自检入口独立为 `DabanQuantSelfTest.exe`，使用 `QCoreApplication`，不依赖窗口系统。
- **CDN DNS 波动**：`push2ex.eastmoney.com` 走 CDN，IP 频繁轮换；极端情况下 Qt 的
  DNS 后台线程可能解析失败，`HttpClient` 已内置重试与降级。
