## 1. 快速开始

### 依赖
| 组件 | 版本 | 说明 |
|---|---|---|
| Qt | 6.8.3 msvc2022_64 | 需含 Widgets / Network / Sql / PrintSupport |
| MSVC | 2022 Build Tools (14.44) | C++17 |
| Windows SDK | 10.0.26100.0 | rc.exe / mt.exe |
| CMake + Ninja | ≥3.21 | |
| QCustomPlot | 2.1.1 | 已内置于 `third_party/qcustomplot/`（GPL） |

### 构建
```bat
build.bat
```
`build.bat` 通过 `tools/detect_env.bat` **自动探测** Qt / MSVC / Windows SDK / MySQL，
再手动注入 `INCLUDE` / `LIB` / `PATH`（不调用 `vcvars64.bat`，因为后者依赖 `reg.exe`，
在受限/沙箱环境中可能被应用控制策略拦截）。探测结果不匹配时用环境变量覆盖：
`QTDIR`、`VSINSTALLDIR`、`VCVER`、`SDKVER`、`MYSQLDIR`；`build.bat --check` 只打印探测结果。

产物：
| 文件 | 用途 |
|---|---|
| `build/DabanQuant.exe` | GUI 客户端（主程序） |
| `build/DabanQuantSelfTest.exe` | 无头自检（验证数据/策略/存储全链路） |

### 部署
```bat
package.bat                          :: 一键打包（推荐，产物在项目根目录）
package.bat 1.2.0                    :: 指定版本号
```
`package.bat` 会依次完成：清理暂存目录 → 复制 Release 主程序 → `windeployqt` 部署 Qt 运行时
（含 `sqldrivers/`、`platforms/`、`imageformats/`、`styles/`、`tls/`）→ 复制 **VC 运行库**与
**`libmysql.dll`** → 复制 `notify_config.example.json` → 压成**扁平** zip
（`DabanQuant_v<版本>_<YYYYMMDD>.zip`，不含顶层目录）→ 从暂存目录跑一次 `--version` 冒烟，
确认依赖齐全再判定成功。

> **VC 运行库必须显式带上**：`windeployqt --compiler-runtime` 依赖 `VCINSTALLDIR`，
> 而本机的 SDK 是由 `build.bat` 注入的（未系统安装），因此该参数实际不生效。
> 脚本改为从 `C:\Windows\System32` 逐个拷贝 `msvcp140* / vcruntime140* / vccorlib140 / concrt140`，
> 否则分发包在**未装 VC 运行库的干净机器上会启动失败**。

> **`libmysql.dll` 必须与 exe 同目录**：受限终端的设备保护策略允许从程序目录加载配套 DLL，
> 从 MySQL 安装目录直接加载会被判定违规并**直接终止进程**（详见 §8.1）。

SQLite 驱动以插件形式存在，**必须**一并部署 `sqldrivers/qsqlite.dll`，否则数据库功能不可用。

### 两处部署目录，别搞混

| 目录 | 角色 | 内容 |
|---|---|---|
| `build/dist/<包名>/` | **暂存区** | `package.bat` 每次从头重建，压缩成 zip 的源；用完即弃 |
| `dist/` | **实跑目录** | 「双击 `DabanQuant.exe` 即可运行」的部署目录，**用户实际启动程序的地方** |

`package.bat` 的第 8 步会把暂存区**同步**到 `dist/`，规则是：

- 二进制（exe / DLL / 插件目录）**全部换新**，并清掉新版本不再需要的残留文件；
- **运行时数据一律保留** —— `dist\daban_quant.db`（交易日志与本地库）与 `dist\backups\`
  （每日数据库备份）属于用户资产，升级既不覆盖也不删除。

> 早期版本的打包脚本只写 `build/dist\`，没同步 `dist\`，导致 `dist\` 里长期停留在老版本
> 而分发 zip 却是新的 —— 同一台机器上「运行的」和「发出去的」不一致。
> 现在第 8 步是打包流程的一部分，并输出同步结果（exe 字节数 / 清理数 / 保留的运行时文件数）。

> 若 `%APPDATA%\DabanQuant\` 可写，数据库默认落在那里；只有该目录不可写（受限环境）时
> 才回退到程序所在目录 —— 也就是 `dist\daban_quant.db`。

数据库默认落在 `%APPDATA%\DabanQuant\daban_quant.db`；若该目录不可写（受限环境），
自动回退到程序所在目录。

### 运行
```bat
DabanQuant.exe                      :: GUI（打开即见做多计划）
DabanQuant.exe -d 2026-10-22        :: 指定交易日
DabanQuant.exe --uismoke            :: UI 冒烟（校验首屏荐股表非空且区间齐全）
DabanQuant.exe --chartsmoke         :: 图表冒烟（日/周/月 + MACD/KDJ/RSI 逐图落 PNG）
DabanQuant.exe --corechecks         :: 离线门禁（与 DabanQuantCoreChecks.exe 同一份断言）
DabanQuantSelfTest.exe --selftest   :: 无头自检（输出到 stdout）
DabanQuantSelfTest.exe --selftest -d 2026-10-22  :: 指定交易日的自检
```

> **为什么有 `--corechecks` 这个入口**：断言集只有一份（`src/tests/CoreChecks.cpp`），
> 被 console 门禁与 GUI 目标**共用**。受管控终端的应用控制策略会拦截**新编译出来的
> console 可执行文件**（`blocked by your organization's Device Guard policy`，exit 4551），
> GUI 目标在白名单内 —— 没有这个入口，离线门禁在那类机器上根本跑不起来。
> 两处跑的是同一份断言，不存在结果不一致的可能。

## 2. 界面结构

> **v1.2.0 起（2026-11-06，UI 优化 P0 + P1）**：
> P0 把「执行类信息」前置到首屏（首页改为「今日计划」），P1 把导航从左侧栏改为**顶部标签栏**、
> 颜色语义收敛为 3 套、并抽出统一组件。见 §10.5 / §10.6。

**整体骨架**（自上而下）：

```
┌ 品牌条 64px ─ 产品名 ｜ 状态 ｜ 仓位读数 ｜ 简洁│详细 ｜ ⋯ 更多 ┐
├ 导航条 44px ─ AI选股结果 交易日志 复盘助手 ┃ 本页主动作 ┤
├ 结论条 38px ─ 今日一句话结论（首页自动收起） ┃ 数据状态角标 ┤
├ 提示条     ─ info / progress / warn / error（4 类反馈，可回看）┤
├ 页面内容   ─ 页标题 + 说明 + 主体 ┤
├ 归因抽屉   ─ 详细视图可见 ┤
└ 状态栏 24px ─ 技术信息（数据源 / 行情时间）┘
```

顶部为**全局状态栏**（始终可见）：市场状态标签（固定中性底色，只给可核对的数字口径；
**界面强调色不再随市场状态切换**——「今天能不能出手」一律由文字结论表达）、建议最大仓位上限、
当日计划仓位与偏离度、**「简洁 / 详细」分段开关**（选择跨会话保留），
以及把全部研究型入口收在一起的**「⋯ 更多」溢出菜单**。

视图档位是「减负担」的核心：**默认简洁视图**，只保留当日执行所需信息；切到**详细视图**才启用
研究型入口 ——「判定依据（情绪闸门原始输入）」「因子权重…」（六维启停 / 权重 / 门槛 / 组合规则）、
「API Key…」与「AI 分析…」（用户自设密钥的大模型解读，详见 §10）、「消息推送…」、
底部**归因与迭代日志抽屉**、决策台的「查看得分由来」/ 维度贡献占比 / 六维明细表、
交易日志的逐笔 AI 诊断栏与复盘页的流程说明。
> 简洁档下这些入口**在菜单里置灰**而不是隐藏 —— 用户知道「有这个能力，只是当前档位不展开」，
> 不会出现「功能不见了」的感觉。档位只控制可用性、不删除任何功能，随时可切回。
> **档位对 5 / 5 页全部生效**（原先只有 2 页有差异，开关会失去可信度）。

导航为**顶部一级标签**（`Ctrl+1` … `Ctrl+3`），右侧是**上下文行动条**：当前页最常做的 2–4 个动作
固定在右上角，不随内容滚动跑掉，也不用每页各发明一套工具条位置。
顶部导航替代左侧栏，直接为数据表腾出 176px 横向空间。
窗口收窄时自动进入紧凑/窄屏两档布局（紧凑档收起顶栏的仓位读数，窄屏档进一步精简品牌条）。

| 模块 | 职责 |
|---|---|
| **AI选股结果**（首页，三页合一：今日计划 + 决策台 + 图表分析） | **顶部今日结论卡**：一句白话结论 + 决策数字（可执行 / 观察 / 建议总仓 / 最晚决策时点）+ 数据状态角标 + 一句人话原因，闸门原文折叠在「▸ 判定说明」里；**12 列计划表**：代码·名称·推荐理由·**买入价**·**目标价**·**止损价**·仓位·**盈亏比**·**止损幅度**·**成交概率**·状态·**K线**（含第二梯队备选，按仓位降序，每行带行内「K 线」按钮，双击行同样触发）；**执行卡停靠表格右侧**（宽屏）/ 收成**顶部一行摘要**（窄屏），竞价结论、成交概率依据、风险标记、白话定价依据与**可用本金换算**随选中行联动；表格下方**标的详情页签**随选中行联动 ——「**K线图表**」（日/周/月 · MA/BOLL · MACD/KDJ/RSI · 缩放/光标读数/涨停标记）与「**决策依据**」（交易计划条 + 入选价格走势 + 维度贡献占比 + 六维明细 + 综合分/打板分「查看得分由来」，后三者在详细视图显示）；**今日提醒清单**、**风控设置折叠区**与**「为什么没选」折叠清单**（含筛选漏斗摘要与逐只淘汰明细）收在下方 |
| **交易日志** | 成交流水台账：从今日计划一键**记录买入**、手工新增、**编辑**补录卖出信息；**3 视图分段开关**（持仓中 / 全部流水 / 已了结）+ 关键字搜索 + 排序 + **CSV 导出**；**13 列流水表**，其中「**下一步动作**」列直接给出持仓期唯一要执行的动作（止损离场 / 分批兑现 / T+1 可兑现 / 持有待涨 / 持有观察 / 待行情），计划价、纪律、备注收进 tooltip 与底部详情栏；**持仓中按现价实时算浮动盈亏**；统计卡分 **4 个主 KPI**（胜率 / 累计盈亏 / 持仓浮盈 / 最大回撤，22px）+ **6 个次指标**（15px）；持仓标的跌破计划止损时自动告警；**每笔自动生成 AI 诊断**（盈亏原因 / 止盈建议 / 回本可行性，见 §2.4）；**流水持久化到 MySQL**（不可用时自动回退本地 SQLite，页面顶部实时显示当前后端） |
| **复盘助手** | **决策复盘为主**：信号溯源（当时的核心条件逐条带数值/阈值/来源）→ 预期 vs 实际偏差（MFE/MAE/目标偏差）→ 被跳过的机会（事后统计）→ 持仓隐性风险（RSI 极端超买 / 低点下移假企稳 / 上方多层阻力）→ 板块轮动客观数据（领涨领跌板块的资金流）；支持切换交易日回看。原市场复盘 / 早盘简报 / 预判准确率保留为辅助页签，详见 §2.5 |

> **颜色语义只有 3 套**（详见 `ui/Theme.h`）：
> **A 行情方向**（红涨绿跌）只用于价格与涨跌幅；
> **B 决策状态**（通过 / 警示 / 危险 / 中性）只用于结论与状态，一律用**带底色的徽章**呈现 ——
> 形状差异保证不靠颜色单独传达信息，也让色觉障碍用户能分辨；
> **C 强调色**（靛蓝，**唯一**）只用于可交互、焦点与当前选中。
> 原先强调色与涨跌色同属红区，「红色」同时表示涨 / 危险 / 选中 / 一致看多，颜色映射无从建立。

> **补能力三项（面向散户执行）**：
> - **③ 本金换算**：执行卡内填一次可用本金，自动把「建议仓位 6%」换算成可买股数（按 100 股取整）
>   与按计划止损计算的最坏亏损金额、占本金比例；本金不足 1 手时明确提示。
> - **⑤ 今日提醒**：6 个关键条件 —— 9:25 竞价判定、进入买入区间、触及止盈、跌破止损、
>   T+1 可卖、14:45 收盘前核对。盘中每分钟检查，命中后状态栏 + 窗口标题 + 声音提示，
>   清单对应项打勾；缓存 / 历史数据不触发价格提醒，**只提醒、不代下单**。
> - **⑦ 风控限额**：首次风险适配说明与确认，以及自设单笔最大亏损、单日最大亏损、
>   单票最大仓位、连亏几笔进入冷静期；命中任一条件即暂停「记录买入」并写明原因
>   （当日盈亏与连亏笔数取自交易日志，每 5 分钟重算）。
>

## 2.1 交易计划：三个区间怎么来的

定价有**两套锚点**，互为印证：

- **价格锚**：涨停价 ± 容忍度、MA5、涨停当日最低价 —— 机械、可预测
- **筹码锚**：由日 K 重建的**成本分布**（筹码密集峰）—— 回答「真实的支撑与压力在哪」

| 区间 | 语义 | 锚点 |
|---|---|---|
| **买入区间** | T 日收盘视角下的承接带（不是最终买点，最终买点看竞价） | 下沿 = **承接位** = 当前价下方最近的**筹码密集峰上沿**（筹码断层时退回 MA5，再退回涨停价 −2%~3%）；上沿 = 涨停价 + 追高容忍（首板 +3% / 二板 +2% / 三板+ 不给溢价） |
| **次日竞价** | **打板真正的执行点**：高开多少能接、多少放弃、竞价量能够不够 | 由连板高度生成价格带（如「接 13.62~14.57，跌破 13.20 放弃」）；9:25 后自动用真实竞价数据判定「可接力 / 观察 / 放弃」 |
| **止盈区间** | 分批兑现价格带 | 下沿 = **买入上沿 × (1+2%)**（保证在上沿成交也有正收益），若落在**上方筹码压力密集区**内则抬到压力区下沿；上沿 = **压力密集区上沿**（收敛后不再高于次日涨停价） |
| **止损区间** | 跌破下沿无条件走，跌破上沿减仓 | 上沿 = **支撑密集峰下沿**（跌破 = 买入逻辑被破坏），其次涨停当日最低价（炸板即走），再次涨停价 −5%；受「最大止损空间」约束（10cm 5% / 20cm 7%） |

**盈亏比（保守口径）** = (止盈下沿 − 买入中枢) / (买入中枢 − 止损中枢) —— 不假设能拿到次日涨停；
乐观口径（按次日涨停兑现）仅在详情里作对照，不参与决策。
**建议仓位** = 情绪阶段总仓上限 ÷ 集中只数（默认 2）× 评分系数 × 题材效应系数；结构止损过远时减半或直接降级。

> 闸门拦截（退潮/冰点）时**仓位恒为 0**，但区间照算 —— 输出「观察名单」供情绪修复时参考。
> 竞价判定为「放弃」时，即使闸门放行也会把该标的从「可执行」降级。

### 2.1.1 筹码分布 · 量能过滤 · 破位判定

`core/ChipDistribution` 用**不复权真实价**日 K 重建成本分布：每根 K 的成交量按**三角形分布**
（峰顶取当日均价）摊到 `[最低价, 最高价]`，再按每日 0.985 的衰减系数加权（越新的筹码权重越高），
落到 140 格价格网格上；平滑后取**半高宽**为峰区上下沿，输出下方最近支撑峰与上方最近压力峰。

| 环节 | 判据 | 动作 |
|---|---|---|
| 筹码支撑 | 下方最近密集峰上沿（峰顶低于现价、筹码占比 ≥2%） | 作为买入下沿（承接位） |
| 筹码压力 | 上方最近密集峰上沿 | 止盈上沿收敛到压力区；进入压力区而量能跟不上 → 减仓提示 |
| **缩量衰竭** | 量比 < 0.8 | 抛压有限，支撑可信（正常持有） |
| **温和放量确认** | 量比 1.5~2 且收盘站上承接位、且高于日均价 | 买盘介入真实（加分项） |
| **放量击穿** | 量比 ≥ 1.5 且收盘跌破承接位、且买盘不接力（收盘位置偏低） | **支撑正被主动卖盘击穿 → 不应买入，降级观察** |
| **量价背离** | 量比 < 0.8 且（涨幅收窄 或 长上影）出现在压力区 | 派发嫌疑，触发卖出预警 |
| **放量破位** | 收盘跌破支撑密集峰下沿 且 量比 ≥ 1.5 | 止损条件当场成立 → **降级观察，不新开仓** |
| **缩量破位** | 量比 < 0.8 | 破位可能是假跌破 → 止损缓冲放宽到 **2.5%** |
| 常规破位 | 其余 | 止损缓冲 **1.5%** |

> **关于分时明细（外盘/内盘、逐笔主动买卖）**：本项目当前**没有逐笔与分时数据源**
> （数据层只有涨停池 / 快照 / 日 K / 题材），因此这些微观确认信号用**日线口径的等价代理**实现：
> 「主动买强度」= (收盘−最低)/(最高−最低)（收盘越靠近最高，买方越主动），
> 「分时均价线」≈ 当日成交均价 `amount/volume`（收盘低于均价 = 全天弱势、反抽无力）。
> 等价物的边界在 `buyBasis` 文案里会写明，不把日线推断冒充成逐笔事实。


> **候选池数量优先 / 小资金推荐 2 只**：候选池保留全部通过筛选的标的，并额外并入分层量价
> 差一点的第二梯队备选（`RecommendBundle::backups`，仅决策台展示）；但仓位摊分与推荐名单
> 共用同一口径 `kConcentratedPositionCount = 2`，即**只有综合分前 2 只可执行并给仓位**，
> 其余留在池内标注「备选 / 观察」。这样既不会因为池子只有 2 只而看不清竞争关系，
> 也不会出现 5 只各按 1/2 总仓摊分、合计远超情绪上限的偏差。

## 2.3 盈亏计算口径（交易日志）

| 项 | 口径 |
|---|---|
| 成本金额 | 买入价 × 数量 |
| 买入费用 | 佣金 万 2.5 |
| 卖出费用 | 佣金 万 2.5 + 印花税 千 1（合计 0.125%） |
| 已实现盈亏 | 卖出价 × 数量 − 成本金额 − 买入费用 − 卖出费用 |
| 持仓中（浮动）盈亏 | 现价 × 数量 − 成本金额 − 买入费用 − 卖出费用（卖出费用按现价预扣） |
| 盈亏比例 | 盈亏金额 ÷ 成本金额 × 100% |
| 未计入 | 过户费、券商「最低 5 元佣金」门槛 |

持仓中的现价取自全市场快照：进入交易日志页、快照更新、盘中自动刷新、点「刷新行情」都会重算；
**拿不到现价时显示「无行情」，不做 0 元估算**（停牌或行情未就绪）。
已实现与浮动共用同一个 `TradeRecord::pnlAt(price)`，因此「累计盈亏」与「持仓浮动盈亏」口径一致。

### 2.4 交易日志的 AI 诊断（`analysis/TradeAdvisor`）

每笔记录在进入日志页时**自动生成**一份可解释诊断，表格「AI 诊断」列给出短标签
（浮盈·分批止盈 / 浮盈·持有待涨 / 浮亏·可修复 / 浮亏·有条件 / 浮亏·已破位 / 已了结·盈利复盘 …），
选中行后在底部右栏按固定结构展开：

| 区块 | 回答什么 | 关键输入 |
|---|---|---|
| **① 盈亏原因** | 这笔为什么赚 / 亏：入场执行（买价 vs 计划中枢）、兑现位置（现价 vs 计划止盈）、趋势结构（MA5/10/20 与斜率）、量能（量比 × 当日涨跌）、持有周期（打板 T+1 口径）、双边费用、离场后走势、情绪阶段 | 成交记录 + 快照 + 日 K + 情绪阶段 |
| **② 止盈建议** | 盈利单用哪套策略、每一步在哪触发、依据是什么：**分批兑现（50%/30%/20%）**、**移动止盈**（MA5 与 1.5×ATR 取高者）、**保本止盈**（含费成本上方 0.2%）、**时间止盈**（T+5 未达目标减半）、利润回吐超过峰值 1/3 时立即减半 | 计划止盈 + 筹码压力峰 + MA5 + ATR14 |
| **③ 回本可行性** | 亏损单的**含费回本价**、还需涨幅、修复价位区间（第一压力位 → 回本价）、预计交易日区间、需要满足的条件（站上 MA5 / 放量 1.2 倍 / 突破筹码压力区 / 情绪修复）与硬约束（跌破计划止损、放量下跌、超期未修复） | 含费成本 + 均线 + ATR + 筹码分布 + 情绪阶段 |

口径约定：

- **回本价含双边费用**：`breakeven = buyPrice × (1 + 买入佣金率) ÷ (1 − 卖出费率)`，
  比买入价高约 **0.15%**；盈利单也会显示该价，作为「不许盈利回吐成亏损」的保本线。
- **预计天数不是价格预测**：按 `ATR% × 0.35` 的修复斜率折算，再按趋势 / 情绪修正，
  输出区间（如 3~7 个交易日），并在诊断栏注明依据。
- **已了结的亏损**没有「等待回本」路径：改为回答「后续同等本金需盈利 x% 才能抹平」，
  并给下一笔的准入条件；离场后走势（卖出价至今）用于判断卖点是否合理。
- **数据缺失即降级**：没有日 K 时只用计划价 + 费用口径；没有现价时标「待行情」，
  不编造盈亏。诊断结果随行情 / K 线 / 情绪阶段变化自动重算，不额外发网络请求。
- **CSV 同步导出**：`AI诊断 / 盈亏原因 / 止盈策略 / 止盈执行 / 回本可行性 / 含费回本价 /
  还需涨幅% / 预计天数 / 风险提示` 九列随流水一起落盘，便于事后复盘。

> **口径区分（重要）**：本节的「AI 诊断」是**本地可解释推理引擎**（规则 + 指标折算），
> 不是大模型调用，离线可用、结果可复现、不需要任何密钥；每条结论都能回溯到具体数字。
> 顶栏「AI 分析…」是另一个独立功能——调用用户自设 API Key 的大模型做结构化解读，
> 其门禁与边界见 §10。两者不共用入口、不共用数据出口，也不互相替代。
> `--selftest` 与 `DabanQuantCoreChecks.exe` 均含本地诊断的对应断言。

## 2.5 决策复盘（收盘后回答「我当时到底是怎么想的、这个想法站不站得住脚」）

> 本节对应 2026-11-08 的复盘助手改造。**它提升的是对自身交易系统的认知，不是替你做一个更聪明的赌徒**：
> 只做**事后核对**，不预测涨跌、不生成新的买卖 / 仓位指令、不改任何交易阈值，
> 也不因为「后来涨了」就给当时的跳过决策打分。所有结论都附
> **实测值 + 判定式 / 阈值 + 数据窗口 + 数据来源**，可逐条复算。

### 2.5.1 五个结构化视图

| 页签 | 回答什么 | 关键字段 |
|---|---|---|
| **信号溯源** | 当时买入 / 离场信号的核心条件是什么、各是多少、门槛是多少 | `SignalTrace.conditions`（逐条 `Evidence`：名称 / 角色 / 实测值 / 判定式 / 是否成立 / 来源窗口 / 口径限制）、`expectation`（当时的计划价与仓位） |
| **预期 vs 实际** | 信号发出后实际走势与策略预期差多少 | 信号日收盘、计划止盈 / 止损、窗口内最高 / 最低 / 末收、**MFE / MAE / 目标偏差 %**、是否触及止盈 / 止损、观察交易日数 |
| **跳过的机会** | 当时没执行的信号后来走了多远 | 未执行判定条件、后续最高 / 最低 / 末收、触及止盈 / 止损、**机械假设收益**（扣双边费用）、口径与不包含项 |
| **持仓隐性风险** | 持仓里有没有没被明显摆出来的风险 | RSI 极端超买 / 低点下移·假企稳 / 上方多层阻力，每项都带实测值与判定式 |
| **板块轮动数据** | 当日领涨 / 领跌板块的资金流向（**不是猜题材持续性**） | 板块涨跌幅、主力净流入（亿元）、主力净占比、字段来源、抓取时间、数据缺失原因 |

原「市场复盘 / 早盘简报 / 预判准确率 / 经验教训」保留为两个辅助页签，
**不参与决策复盘的任何结论**；规则权重迭代仍只作用于市场预判，不改交易阈值。

### 2.5.2 判定条件（与代码共用同一份常量 `DecisionReview::Criteria`）

| 项 | 阈值 / 判定式 | 数据窗口与口径 |
|---|---|---|
| 均线收敛度 | `(max(MA5,MA10,MA20) − min) / MA20 × 100% ≤ 1.50%` | 前复权日 K，截至复盘日近 20 根；**观测指标，不是现行买入信号的触发字段** |
| RSI | `RSI6 ≥ 80.0` 判极端超买，`≥ 70.0` 判超买 | Wilder 口径，与图表副图 RSI(6/12/24) 一致；**不是现行买入信号的触发字段** |
| 资金流入 | 主力净流入 `> 0.00 亿元`（个股详情 `fflow`）；无该字段时用 `封单额/成交额 ≥ 0.20` 的**量能代理并明确标注** | 免费选股接口没有主力净流入字段；两者都缺即标「数据缺失」，不填 0 |
| 假企稳 | `收敛度 ≤ 1.50%` **且** 最近 `3` 个 `5` 日窗口低点严格递减 **且** 斜率 `< 0%` | 前复权日 K 摆动低点；结论里列出每个窗口的具体低点价 |
| 上方多层阻力 | 当前价上方、筹码占比 `≥ 2%` 的密集峰 `≥ 2` 层 | 不复权日 K 重建成本分布（三角分布 + 0.985 衰减），列出每层价格区间与占比；相邻峰顶差 <0.5% 视为同一层 |
| 事后观察窗口 | 信号日之后最多 `5` 根日 K（**不含信号日**） | `MFE = 最高/基准−1`、`MAE = 最低/基准−1`、`目标偏差 = (窗口最高−止盈下沿)/止盈下沿×100%` |
| 跳过判定 | 交易日志中不存在 `code` 相同且 `buyDate ∈ [信号日, 信号日+1 自然日]` 的买入记录 | 假设收益 = `末收×(1−卖出费率) / (计划买入中枢×(1+买入费率)) − 1`；不含滑点、成交概率、T+1 限制与资金占用 |
| 领涨 / 领跌 | 当日板块涨幅降序前 3 / 后 3 | 东财 `f3` 涨跌幅、`f62` 主力净流入净额（元→亿元）、`f184` 主力净占比；只陈述当日数值 |

**关于「触发条件」的诚实口径**：现行买入信号由
`情绪闸门 → 分层量价 → 多因子评分 → 交易计划 → 次日竞价` 产生，
界面里逐条列出这些**当时真正用到的条件**（执行标记 / 信号档位与仓位 / 情绪硬闸门 /
多因子过滤 / 区间自洽 / 盈亏比与成交概率 / 竞价结论）。
均线收敛度、RSI、资金流入是**当时可复算的观测值与风险标记**，
在证据表里标注为「观测指标」并写明「不是现行买入信号的触发字段」——
不把后见之明包装成当时的触发逻辑。

### 2.5.3 数据来源、留档与降级

| 数据 | 来源 | 留档 |
|---|---|---|
| 当时的计划 | `recommend_plan.payload`（按交易日整包 JSON） | 支持切换交易日回看历史决策 |

## 3. 策略核心：五层流水线

```
L0 情绪闸门 → L1 通用硬排除 → L2 题材效应 → L3 分层量价 → L4 评分排序 + 同题材身位 → L5 交易计划 → L6 次日竞价
```

**关键设计 1：闸门是硬否决。** 跌停 ≥8 家或炸板率 >40% 时直接不出手，而不是靠选股硬扛。
（但仍输出**观察名单**：区间照算、仓位为 0 —— 见 §2.1）
这源于当前市场环境——A 股平均连板高度已从 2015 年约 7 板压缩至约 3.2 板，
打板胜率降至 20%–30%，炸板率长期 45%–60%。

**关键设计 2：先行指标优先于涨停家数。**
情绪闸门除了涨停/炸板家数，还会计算 **连板晋级率**、**首板晋级率**、**昨日涨停股今日平均溢价**。
三者同时走坏时，即使涨停 60 家也会被判为退潮——这正是打板最容易亏钱的一天。
溢价率要求采样覆盖 ≥50%，否则标记「样本不足」且不参与判定（避免用残样本算出 +10% 的假繁荣）。

**关键设计 3：板块效应用「概念题材」，不是行业。**
「算力 / 机器人 / 固态电池」这些题材在申万行业里会散落到不同行业，用行业统计会把主线龙头
判成孤板、把杂毛凑成假板块。客户端拉取东财概念板块（剔除「昨日首板」「融资融券」这类
统计口径伪题材），并按 **涨停家数最多的题材** 归主口径；题材查不到时回退行业，
两者取「更强的一个」，避免新数据反而降级。

**关键设计 4：同题材身位排序。**
评分是绝对分，回答不了「这个题材今天该打哪一只」。排序规则与实盘一致：
**板数 → 首封时间 → 封单额**，身位第一标「龙头」并加分，仓位也向龙头倾斜。

**分层量价（避免最常见的「三层标准混着用」错误）：**
- **首板看换手**：按流通市值分三档（<50 亿 8/10–20/25%、50–200 亿 5/6–15/20%、>200 亿 3/3–8/15%）
- **二板看强度**：封单/成交额 ≥20%、封单/流通市值 ≥1%、量能相对首板 1.2–3 倍
- **三板+看地位**：板块涨停 ≥3 家、≥6 板坚决不碰

阈值统一内置于各引擎的固定常量（`Indicators` / `FilterPipeline` / `Scorer` / `MarketRegime`），
作为固定策略基线，随筛选管线即时生效。

| 单只实时 | `hq.sinajs.cn/list=` | **GBK 编码** |
| 概念板块涨幅 + 主力资金流（复盘用） | `82.push2.eastmoney.com/api/qt/clist/get?fs=m:90+t:3`（`f3/f62/f184`） | `f62` 单位是**元**，展示时 ÷1e8 转亿元；字段缺失或量纲异常一律标「数据缺失」，不用涨幅反推资金流 |

工程约束：
- 东财/新浪需带 `Referer`
- 炸板池必须带 `sort=zbc:desc`，否则 pool 为空
- **跌停池必须带 `sort=fund:asc`，否则 pool 恒为空**（2026-11-04 实测：不带 0 家，带后 10 家；
  曾导致跌停家数恒为 0、「跌停 ≥8 家硬否决」从未生效。可用 `--selftest` 输出的跌停家数独立核对）
- 日 K 需要**两次请求**（`qfq` 前复权 + 不带复权参数）才能同时拿到两套价格；
  只请求 qfq 时接口不返回 `day` 数组，`rawCandles` 会为空（涨停判定与止损锚点就会退回复权价）
- 部分受限网络对 `web.ifzq.gtimg.cn` 返回 `501 Not Implemented`：此时 K 线相关因子自动跳过，
  交易计划退化为「涨停价 ± 百分比」的保守估计，并在依据里显式注明
- 内置**每主机令牌桶**（16 req/s）、并发上限 10、指数退避重试
- **默认不使用 `http_proxy` 环境变量**：实测套用后 Qt 会报 `TLS initialization failed`，
  直连反而正常；如需代理设 `DABAN_FORCE_PROXY=1`

### 5.2 筛选漏斗：回答「涨停 47 只，怎么只剩 2 只」

### 5.3 表格新增的 4 列与分级配色

| 列 | 语义 | 来源 | 配色 |

原来只有 `≥2.0` 才变绿，而保守口径下 RR 普遍在 0.8~1.2，0.83 与 1.5 长得一模一样。

「状态/依据」列压成短标签（可执行 / 竞价否决 / 情绪未触发 / 未过评分门 / 仓位不足 …），
**统一 ≤ 5 个字** —— 表格里被截断的标签等于没有标签；完整文案放悬停提示与执行卡。
原先那一长串既与新增三列重复，又把整列挤出屏幕。
**观察名单整行淡黄底**，与可执行一眼分开。

## 7. 多维度做多因子选股

在完整保留原有打板策略（`L0 情绪闸门 → L1 硬排除 → L2 题材 → L3 分层量价 → L4 Scorer 8 因子`、
五层硬阈值与竞价否决均不变）的前提下，新增一条**纯计算的多因子评分链路**。
五个新增维度与打板核心共同参与综合评分；实盘与回测共用 `MultiFactorEngine::rank()`。

### 7.1 维度定义

| 维度 | 定义（子项权重） | 数据口径 |
|---|---|---|
| 打板核心 | 原 `Scorer` 8 因子：换手/量能/封板时点/封单/题材/高度/涨停基因/均线 | `Candidate.score` |
| 趋势 | 均线多头 0.4 + 收盘/MA20 偏离 0.3 + 收盘/MA60 偏离 0.3 | 前复权日 K |
| 动量 | 近 20 日收益 0.35 + 近 5 日收益 0.25 + 量比 0.20 + 20 日涨停基因 0.20 | 日 K + 候选派生指标 |
| 资金流向 | 封单强度 0.35 + 成交额/20 日均额 0.30 + 换手活跃度 0.20 + 收盘承接位置 0.15 | **代理口径**：免费接口无主力净流入字段 |
| 基本面 | PE 0.25 + PB 0.20 + 流通市值适中度 0.25 + ST/退市风险 0.15 + 换手活跃度 0.15 | 新浪快照 `pe / pb / floatCap` |
| 波动率 | ATR14% 0.50 + 20 日收益标准差 0.30 + 20 日最大回撤 0.20（风险调节，分高 = 波动适中可控） | 前复权日 K |

每个维度先由**可用子项**加权成 0~1 的维度得分，`coverage` 记录子项可用比例；
缺失子项自动剔除并按剩余子项重新归一，不会用 0 分误伤。

### 7.2 权重配置与组合规则

在顶部品牌条点「因子权重…」修改，配置以 JSON 写入 SQLite `app_setting`
的 `factor.config`；GUI 与无头回测读取同一份配置。出厂默认即「**均衡做多**」
（`strategy/FactorConfig::balanced()`）。

| 配置项 | 默认值 | 说明 |
|---|---|---|
| 权重 | 打板 0.35 / 趋势 0.15 / 动量 0.15 / 资金 0.15 / 基本面 0.10 / 波动率 0.10 | 按「启用且数据可用」的维度自动归一化 |
| 启用 | 全部启用 | 可逐维度关闭（全关时强制恢复打板核心） |
| 参与方式 | 叠加 | 叠加 / 过滤 / 叠加+过滤；过滤模式低于门槛即淘汰且不计分 |
| 过滤门槛 | 0.35 | 作用于 0~1 的维度得分 |
| 组合规则 | 加权求和 | 备选「木桶」= 75% 加权分 + 25% 最低维度分 |
| 综合分门槛 | 0 | 低于该分淘汰 |
| TopN | 30 | 输出排名前 N |
| 维度数据缺失即淘汰 | 关闭 | 开启后缺任一维度数据的标的不入榜 |

综合分 `= Σ(归一化权重 × 维度得分) × 100`。被多因子规则淘汰的标的降级为观察名单、
仓位归零并写明原因（与原闸门拦截语义一致）；候选清单按综合分降序输出。

### 7.3 维度贡献度分析

`贡献分 = 归一化权重 × 维度得分 × 100`，**各维度贡献之和等于综合评分**；
`贡献占比 = 贡献分 / 综合评分`。

- 逐只标的：决策台「评分维度明细」给出每个维度的得分、有效权重、贡献分、占比与状态；
- 当日级：底部归因抽屉给出各维度平均贡献分与平均占比，用于评估该维度对最终选股结果的影响；
- 回测级：逐笔 CSV 增加 `composite / factor_rank / share_*` 列，`--backtest N`
  输出回测期各维度平均贡献与配置指纹。

### 7.4 实盘 / 回测一致性

- 两条链路都调用 `MultiFactorEngine::rank()`，输入统一由 `makeInputs()` 构造并
  `sliceTo(asOf)` 截断，配置来自同一份 `factor.config`；
- 实盘：`RecommendEngine::build()` → `applyFactorRanking()` 写回 `TradePlan`
  → 首页缓存 / 决策台 / 推送；回测：`BacktestRunner::run()` 直接调用 `rank()`，
  被过滤或未入 TopN 的标的不参与结算；
- `--selftest` 含「实盘/回测综合评分一致」断言，离线门禁 `core_checks` 验证
  权重归一化、贡献度守恒、过滤规则与统一输入构造；
- **已知限制**：历史快照未落库，回测侧基本面仅用市值/换手等可得子项，资金流向为
  代理口径；引擎显式标注覆盖率并自动重分配权重，不会静默补 0。

### 7.5 策略口径：均衡做多（单套配置）

版本管理功能已下线，全局**只保留一套因子权重**：

| 策略 | 定位 | 配置要点 |
|---|---|---|
| 均衡做多（唯一保留） | 六维均衡 | 打板 35% + 趋势/动量/资金各 15% + 基本面/波动率各 10%，加权求和 |

- **入口**：顶部品牌条「因子权重…」按钮，保存后首页计划 / 决策台 / 缓存 / 推送 / 回测 CLI
  立即按新权重重算，无需重启；
- **持久化**：配置存 `app_setting.factor.config`，供 GUI 与 `--backtest N` 共用，保证实盘/回测同口径；
- **升级迁移**：检测到旧版 `app_setting.strategy.versions` 时，自动取其中启用版本
  （优先「均衡做多」）的权重迁移到 `factor.config`，迁移后旧键不再被读取。

### 7.6 候选池「仅推荐两只」口径

小资金集中持仓口径由 `core/TradePlan::applyConcentratedPicks()` **唯一实现**，决策台与候选池面板共用：

| 规则 | 说明 |
|---|---|
| 名额 | 只有「可执行且有建议仓位」的标的才占用推荐名额，**最多 2 只**（`kConcentratedPositionCount`） |
| 分配 | 名额按**综合评分**从高到低分配，与列表显示顺序解耦 —— 排序变化不影响名额归属 |
| 落选 | 落选的可执行标的降级为「备选」：`actionable=false`、仓位归零，note 写明「名额已满」的原因 |
| 观察名单 | 本就不可执行的标的不占用名额，也不会被误标成「推荐」 |
| 幂等 | 重复应用结果不变，决策台与候选池面板先后调用不会互相干扰 |

顶部结论条与候选池标题的「推荐 N 只」都按此口径输出（N ≤ 2）。

### 8.1 交易日志的 MySQL 存储

交易日志（成交流水）是唯一需要长期留档、可能跨设备查看的数据，因此**优先写入 MySQL**，
本地 SQLite 只作兜底。两套后端都实现同一个 `storage/JournalStore` 接口，
界面层不感知差异，切换后端不需要改任何 UI 代码。

| 项 | 说明 |
|---|---|
| 默认连接 | `root@127.0.0.1:3306/daban_quant`（密码按部署要求内置，首次连接成功后用 DPAPI 加密写回 `app_setting`，之后不留明文） |
| 建库建表 | 首次连接自动 `CREATE DATABASE IF NOT EXISTS` + `CREATE TABLE IF NOT EXISTS`（`trade_journal`，字段与 SQLite 后端一一对应） |
| 客户端库 | MySQL Connector/C（`libmysql.dll`）。**必须与 exe 放在同一目录**：受限终端的设备保护策略允许从程序目录加载配套 DLL，从 MySQL 安装目录直接加载会被判定违规并**直接终止进程** |
| 落地方式 | 运行时 `LoadLibrary` 动态加载（静态导入会让 exe 在启动时被策略拦截） |
| 兜底策略 | 连接失败（服务未启动 / 密码不对 / 找不到客户端库）→ 自动回退本地 SQLite，页面顶部显示当前后端与失败原因，**记录买入等功能永远可用** |
| 历史搬迁 | 升级后首次成功连接时，把本地 SQLite 里的历史流水按「代码 + 买入日 + 买入价 + 数量」去重后并入 MySQL |

构建期开关：`CMakeLists.txt` 的 `DABAN_ENABLE_MYSQL_JOURNAL`（默认 `ON`）。
关闭后交易日志只写本地 SQLite —— 适合没有 MySQL 客户端库的机器。

### 10.3 AI 分析的思路与边界（固定契约，不可由对话扩展）

**调整结论**：AI 分析不是「开放式问答」，而是一个**输入受限、输出定结构、判断有原则**的解读器。
四段契约统一定义在 `analysis/AiAnalysisSpec.*`，同时作为 system prompt、界面说明与输出校验的唯一来源，
界面上以「分析边界（固定，不可由对话改变）」整块展示，用户可见、可核对。

**① 分析目标**（只回答什么）
- 只解读本次提供的**单个结构化计划快照**：核对区间数值是否自洽、复述计划已写明的纪律、指出快照中可见风险。
- **不做**：价格 / 涨跌预测、生成新的买卖或仓位指令、选股、替代情绪闸门与仓位计算、给出目标价与胜率。

**② 输入信息范围**（白名单，超出即丢弃）

| 类别 | 允许字段 |
|---|---|
| 标识 | `tradeDate`、`code`、`name` |
| 区间 | `buyLow/buyHigh`、`takeProfitLow/takeProfitHigh`、`stopLossLow/stopLossHigh` |
| 数值 | `riskReward`、`positionPct`、`score`、`sentimentComposite`、`positionCapPct` |
| 状态 | `actionStatus`、`riskFlags`、`gateAllowed` |
| 本地结论 | `localDiagnosis`（≤120 字的数字摘要） |

- `AiSpec::sanitizeInput()` 按固定顺序重建对象：白名单外字段（账户资金、备注长文、原始 K 线、
  快照全量数据、`apiKey` 等）一律丢弃；类型不符或缺失一律置 `null`；文本与数组均有长度 / 条数上限。
- 界面在提交前**原文展示**这份过滤后的 JSON，用户可核对「到底发了什么」。
- **禁止**：外部知识、实时行情、网络检索、账户 / 资金 / 个人信息、密钥、白名单外的任何文本。

**③ 输出内容结构**（严格 schema，不合规整份丢弃）

```json
{
  "conclusion": "一致 | 存疑 | 数据不足",
  "summary": "≤120 字",
  "evidence": [ { "field": "白名单字段名", "observation": "≤60 字" } ],
  "risks": ["≤60 字"],
  "discipline": ["≤60 字"],
  "uncertainty": "≤80 字"
}
```

- 键集合**固定且不多不少**，全中文，不允许 Markdown / 代码围栏（解析时仅容忍一层 ``` 包裹）。
- `evidence` ≤5 项且 `field` 必须命中白名单；`risks` ≤5、`discipline` ≤3，均为字符串数组。
- 校验失败（多余键、缺键、枚举非法、类型不符、超长、引用白名单外字段）→ **整份丢弃**并提示
  「输出不符合约定结构，已整份丢弃：<原因>」，**不展示半截结果**，避免输出不一致。
- 合规结果统一渲染成固定 5 段：① 结论摘要 ② 依据 ③ 可见风险 ④ 计划纪律 ⑤ 不确定性，末尾附免责声明。

**④ 判断原则**
1. 每条结论都要能在 `evidence` 找到对应输入字段，只引用给定数字与标记，**不得编造数据**。
2. 只复述计划已有的区间与纪律，不给目标价 / 胜率 / 买卖时点，**不构成投资建议**。
3. 输入互相矛盾（如止损下沿 ≥ 买入上沿）→ `存疑`；关键字段缺失（值 `null`）→ `数据不足`。
4. 与本地规则诊断不一致时**以本地计算结果为准**，AI 只标注差异，不改写任何数值。
5. 每次请求独立、无历史上下文、`temperature = 0`；不回显密钥与请求头，不产生额外请求。
6. 数据不足时如实标注，不允许用常识补齐；输出仅供参考。

**一致性保障**：`systemPrompt()` 直接由上述四段文本拼装，改一处即全链路生效；
请求体由 `buildRequestBody()` 统一构造（内部再过滤一次白名单），解析由 `parseResult()` 统一收口，
渲染由 `renderResult()` 统一收口；任何 UI 分支都不能自定义 prompt、自定义字段或自定义结论文案。

**验收**：`DabanQuantCoreChecks.exe` 的「AI 分析边界」8 条断言通过（含越界字段丢弃、
密钥不进请求体、四段 prompt 固定、多余字段 / 非法枚举 / 引用外部字段 / 类型不符 / 非 JSON 整份丢弃）；
界面「分析边界」与「本次提交的输入」两处内容与代码常量一致。

### 10.7 三页合一：「AI选股结果」（基线 2026-11-06）

**调整结论**：原「今日计划 / 决策台 / 图表分析」三个独立页面合并为统一的
「**AI选股结果**」页，替代原有三个导航入口。三者能力**完整继承**，并以
「每只入选标的的 AI 选股结果」为主线重组：选中一只标的，它的 AI 结论、
决策建议、判断依据与 K 线图表在**同一屏内就地联动**，不再跨页跳转。

**页面结构（自上而下）**：

```
┌ 今日结论卡 ─ AI 总结论 + 决策数字 + 数据状态角标（闸门原文折叠）┐
├ 工具条     ─ 筛选 / 列 / 搜索 / 统计读数                      ┤
├ 上：12 列计划表（含备选） ｜ 执行卡 320px（宽屏停靠 / 窄屏摘要）┤
├ 下：标的详情页签（垂直可拖 QSplitter）                        ┤
│     [K线图表] ← 原「图表分析」整页嵌入                        │
│     [决策依据] ← 原「决策台」中栏整页嵌入                     │
├ 提醒清单 / 风控折叠 /「为什么没选」（漏斗摘要 + 淘汰明细）      ┤
└ 归因抽屉（全局，详细视图）                                    ┘
```

**信息层级与能力继承**：

| 原页面 | 继承方式 |
|---|---|
| 今日计划 | 结论卡 / 12 列计划表 / 执行卡（宽窄屏契约不变）/ 提醒 / 风控 / 执行单 /「为什么没选」**原样保留** |
| 决策台 | 候选池（plans + backups，按代码去重）**并入计划表**（`applyConcentratedPicks` 兜底）；筛选漏斗由「为什么没选」折叠区承载（既有等价物）；六维明细 / 维度贡献占比 /「查看得分由来」/ 入选价格走势收进「决策依据」页签 |
| 图表分析 | ChartPanel 整页嵌入「K线图表」页签，周期 / 指标 / 缩放 / 光标 / 涨停标记全部保留；数据仍走 480 日长历史独立通道 |

**数据流向与去重**：

- `RecommendBundle` 仍由 `MainWindow::updateRecommend()` **单点计算**，合并后只扇出
  一次：`m_recPanel->setBundle()`（原决策台的第二份 bundle 拷贝随 DecisionDesk 一并删除）；
- K 线缓存改为**指针共享**（`setMarketContext(&m_klines, sent)`），面板不再复制整表
  （原 DecisionDesk 各存一份哈希副本的去重点）；情绪状态为小对象按值传递；
- 图表数据仍由 MainWindow 的 `chartKlineReady → renderChart → showKline` 通道喂给
  嵌入的 ChartPanel（`AiStockPanel::chartPanel()` 暴露入口），与筛选 120 日缓存互不污染。

**交互逻辑**：

- **单击行** → 执行卡 + 「决策依据」页签联动（不切页签）；
- **双击行 / 行内「K线」按钮 / 顶栏「看 K 线」** → 就地切到「K线图表」页签并请求该标的
  长历史图表（`candidateSelected` 信号保留，主窗口只渲染不切页）；
- **首次进入「K线图表」页签**且无数据时自动请求当前选中标的；
- **bundle 到达**后无选中行时默认选中建议仓位最高的一只（打开即见完整联动）；
- 快捷键 `Ctrl+1…3`；全局结论条点击直达首页；导航 5 项收敛为 3 项。

**旧功能下线方式**：

- `DecisionDesk`、`CandidateListPanel` 两个类与页面**整体删除**（含源文件与 CMake 条目）；
  其承载的候选池 / 漏斗 / 决策详情能力已按上表分流，无功能缺口；
- `ChartPanel`、`DecisionDetailView` **保留为组件**，从独立页面降级为首页内嵌页签；
- `RecommendPanel` 更名为 `AiStockPanel`（文件同步改名），作为合并后的唯一载体。

**用户迁移路径**：

| 旧入口 | 新位置 |
|---|---|
| 今日计划（首页） | 不变 —— 首页即「AI选股结果」，原内容一屏全在 |
| 决策台 · 候选池 / 备选 | 计划表内（备选与观察名单同表显示，tooltip 说明名额原因） |
| 决策台 · 漏斗 / 淘汰明细 | 「为什么没选」折叠区（原已存在） |
| 决策台 · 六维明细 / 得分由来 | 表格下方「决策依据」页签 |
| 图表分析 | 表格下方「K线图表」页签（双击行 / 行内按钮 / 「看 K 线」直达） |

**新增回归门禁（`--uismoke`）**：

| 断言 | 失败码 | 变化 |

| `nav bar` | 22 | Nav 恰 3 个；「列」菜单仍 = 12 列 |
| `page actions` | 23 | 3 / 3 页均有主动作 |
| `decision detail` | 10 | 「决策依据」六维明细随首屏结果就位（替代原候选池断言） |
